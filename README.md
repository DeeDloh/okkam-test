
## Запуск


```bash
docker-compose up --build -d
```

CSV загружается автоматически при первом запуске.

## Структура

- `app/` — API, расчёт и подключение к БД.
- `init/` — загрузка CSV и подготовка средних весов.
- `Untitled.ipynb` — предварительный анализ: типы, пропуски, распределения и даты.
- `docker-compose.yaml`, `Dockerfile` — запуск API и PostgreSQL.

# Условие

Имеется дамп базы `data.csv` со следующими полями:

- `Date` — дата в формате `yyyymmdd`.
- `respondent` — уникальный номер респондента.
- `Sex` — пол респондента (`1` = М, `2` = Ж).
- `Age` — возраст респондента.
- `Weight` — некая статистика респондента для этого дня.

Необходимо:

1. Загрузить данные в таблицу СУБД SQL на ваш выбор (но не SQLite).
2. Разработать API с одним GET-эндпоинтом `/getPercent`, который будет выполнять следующий алгоритм:
   1. На вход эндпоинта приходят два параметра: `audience1` и `audience2`.
      Аудитории будут приходить в формате SQL-синтаксиса, например
      `Age BETWEEN 18 AND 35` или `Sex = 2 AND Age >= 18`.
   2. Для каждой из аудиторий отобрать из таблицы всех респондентов, подходящих под параметры.
   3. Для каждой из аудиторий взять средний `Weight` респондента этой аудитории,
      сгруппировав по их уникальному номеру.
   4. Далее вычислить процент вхождения второй аудитории в первую,
      основываясь на среднем `Weight`. Пример:
      - Имеем первую аудиторию, в которую входят `resp1` с `avg(Weight) = 1`,
        `resp2` с `avg(Weight) = 2` и `resp3` с `avg(Weight) = 3`.
      - Имеем вторую аудиторию, в которую входят `resp2`, `resp3` и `resp4`
        с `avg(Weight) = 2, 3, 4` соответственно.
      - Аудитории пересекаются респондентами `resp2` и `resp3`, у которых
        `avg(Weight)` равен `2` и `3`. Средний `Weight` не может быть разным
        у одного и того же респондента.
      - Значит, процент вхождения второй аудитории в первую будет равен
        `(2 + 3) / (1 + 2 + 3) = 0.8(3)`.
   5. Предусмотреть варианты:
      - Аудитории могут быть идентичными.
      - Аудитории могут не пересекаться вообще.
      - Вторая аудитория может быть подмножеством первой.
      - Первая аудитория может быть подмножеством второй.
   6. Отдать ответ в формате `{"percent": результат}`.
3. Обернуть API в Docker-контейнер.
4. Подготовить Docker Compose-конфиг для связки API + СУБД:
   - База данных должна быть создана и наполнена.
   - API слушает порт 80.
5. Опционально:
   - Позаботиться об отказоустойчивости.
   - Позаботиться о быстродействии, учитывая, что данные не будут изменены ретроспективно.
   - Порядок в коде: PEP 8, докстринги, типизация, структура проекта.
